# Contributing to better-auth-tarjim

Thanks for helping! The most valuable contributions are **better Arabic wording** and
**translations for new Better Auth error codes**. No build tooling knowledge is required for either.

## Setup

```bash
git clone https://github.com/raidsobhi/better-auth-tarjim.git
cd better-auth-tarjim
npm ci
npm run check   # sync check + typecheck + tests + build + size budget + smoke
```

Node **22.18 or newer** is required for development (vitest and tsup need it; `.nvmrc` pins 22). The published package itself still supports Node 18+, and CI tests the built output on Node 18 and 20.

## How the project works

- **Better Auth is the source of truth.** `src/codes.generated.ts`, `docs/CODES.md` and `docs/codes.json` are generated
  by `scripts/sync-codes.mjs` from the installed Better Auth packages. Never edit them by hand.
- **`src/ar.ts` is the only hand-written dictionary.** It is typed as `Record<ErrorCode, string>`,
  so TypeScript fails when a code has no translation and when a translation targets a code that no longer exists.
- Translation is always by **error code**, never by English message text, because messages change between releases.

## Adding translations for a new Better Auth release

A scheduled workflow (`.github/workflows/sync-better-auth.yml`) opens a PR whenever Better Auth is updated.
If new codes appeared, the PR fails the type check. To fix it:

1. Check out the PR branch and run `npm ci`.
2. Run `npm run typecheck`. The errors list every code that is missing from `src/ar.ts`.
3. Add each code to the matching section of `src/ar.ts`. Find the English meaning in `docs/CODES.md`.
4. Run `npm run check`, commit, and push.

To sync by hand: `npm i -D better-auth@latest` (and any `@better-auth/*` plugin packages), then `npm run sync`.

## Arabic style guide

- Modern Standard Arabic, friendly and short. Users read these in a toast, so aim for one line.
- Address the user directly (`ليست لديك صلاحية…`, `يرجى تأكيد بريدك…`) rather than describing the system.
- Do not leak implementation details to end users. For developer-facing configuration errors, write a generic, calm message.
- Keep the same term for the same concept: `مؤسسة` (organization), `فريق` (team), `رمز التحقق` (OTP), `مفتاح المرور` (passkey), `الجلسة` (session).
- Use `تعذّر` for "failed to / unable to", and `غير صالح` for "invalid".
- Never include placeholders or English text in a message.

## Documentation site

The documentation site is built with VitePress from the `docs/` directory and deployed to
GitHub Pages by `.github/workflows/docs.yml` on every push to `main` that touches docs.

```bash
npm run docs:dev      # local dev server with hot reload
npm run docs:build    # production build in docs/.vitepress/dist
npm run docs:preview  # preview the production build
```

`docs/CODES.md` and `docs/codes.json` are generated by `npm run sync`, so they never drift from the
shipped code list. The site renders the same data as an interactive table from `docs/codes.json`
(`docs/CODES.md` is excluded from the site and exists for readers on GitHub). Add new
guide pages under `docs/guide/` and register them in `docs/.vitepress/config.ts`.

On GitHub, set **Settings → Pages → Build and deployment → Source** to **GitHub Actions**
once. After that, every push to `main` that changes the docs redeploys the site.

## Pull requests

- One topic per PR; keep the diff small.
- Run `npm run check` before pushing. CI runs the same command.
- Add or update tests for behaviour changes in `src/translate.ts` or `src/index.ts`.
- Add a line under **Unreleased** in `CHANGELOG.md`.
- The runtime must stay tiny: no new runtime dependencies, and the size budget in `scripts/size.mjs` must pass.

## Releasing (maintainers)

1. Update `version` in `package.json` and move the **Unreleased** notes in `CHANGELOG.md` under the new version.
2. Commit, then tag and push: `git tag v0.1.1 && git push origin main --tags`.
3. The `release` workflow verifies the tag matches `package.json`, runs all checks and publishes to npm with provenance.

## Reporting bugs

Please include the Better Auth version, the `error` object you received (`code`, `status`, `message`) and what you expected to see.
